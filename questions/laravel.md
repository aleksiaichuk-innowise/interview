# Памятка для собеседования: Laravel & Infrastructure

## 🟢 Уровень: Junior (Основы и Eloquent)

| # | Вопрос | Ответ |
| :--- | :--- | :--- |
| 1 | **Что такое Service Container?** | DI-контейнер Laravel, который управляет зависимостями классов и их внедрением (Injection). |
| 2 | **Service Providers** | Центральное место настройки приложения. Здесь происходит "связывание" (binding) интерфейсов с реализациями в контейнере. |
| 3 | **Eloquent: Active Record** | Паттерн, где модель напрямую связана с записью в БД. Объект сам умеет себя сохранять, обновлять и удалять. |
| 4 | **Migrations** | "Система контроля версий" для базы данных, позволяющая описывать структуру таблиц в PHP-коде. |
| 5 | **Middleware** | Фильтры для HTTP-запросов (например, проверка авторизации или логирование) перед тем, как запрос попадет в контроллер. |
| 6 | **Blade** | Мощный шаблонизатор Laravel, позволяющий писать PHP-код в удобном синтаксисе, который затем компилируется в обычный PHP. |
| 7 | **Artisan** | Интерфейс командной строки (CLI) Laravel для генерации кода, запуска миграций и других служебных задач. |
| 8 | **Зачем нужен .env?** | Хранение настроек окружения (БД, ключи). Значения из него подтягиваются в конфиги через функцию `env()`. |
| 9 | **Eloquent: save() vs update()** | `save()` работает с экземпляром модели (вставляет или обновляет), `update()` обычно вызывается на Query Builder для массового обновления. |
| 10 | **Что такое Facades?** | "Статический" интерфейс к классам, доступным в Service Container. Упрощают синтаксис (например, `Cache::get()`). |
| 11 | **Validation: Form Requests** | Отдельные классы для выноса логики валидации из контроллера, что делает код чище. |
| 12 | **Eloquent Relationships** | Методы в модели: `hasOne`, `hasMany`, `belongsTo`, `belongsToMany`. |
| 13 | **Что такое CSRF-защита?** | Защита от подделки межсайтовых запросов. Laravel автоматически проверяет токен в POST/PUT запросах. |
| 14 | **Redis в Laravel** | Используется "из коробки" для кэша, сессий и очередей через драйвер `predis` или `phpredis`. |
| 15 | **Команда php artisan tinker** | Интерактивная REPL-оболочка для выполнения PHP-кода в контексте приложения Laravel. |

## 🟡 Уровень: Middle (Бизнес-логика и производительность)

| # | Вопрос | Ответ |
| :--- | :--- | :--- |
| 1 | **Binding vs Singleton** | `bind` создает новый объект при каждом вызове, `singleton` создает объект один раз и возвращает его при последующих вызовах. |
| 2 | **Eloquent: N+1 и Eager Loading** | Проблема лишних запросов в цикле. Решается методом `with(['relation'])`, который загружает связи одним запросом. |
| 3 | **Gates vs Policies** | `Gates` — для простой проверки прав (через замыкания), `Policies` — классы с логикой вокруг конкретной модели. |
| 4 | **Jobs & Queues** | Вынос тяжелых задач (отправка писем) в фон. Laravel поддерживает драйверы Redis, Database, SQS. |
| 5 | **Eloquent Observers** | Классы-слушатели событий модели (`creating`, `updated`, `deleting`), позволяющие вынести побочную логику. |
| 6 | **API Resources** | Слой трансформации моделей в JSON-ответы, позволяющий гибко настраивать структуру API. |
| 7 | **Collections** | Обертка Laravel над массивами с удобными методами (`map`, `filter`, `reduce`), работающая эффективнее сырого PHP. |
| 8 | **Query Builder vs Eloquent** | Query Builder быстрее и потребляет меньше памяти, Eloquent удобнее за счет связей и аксессоров. |
| 9 | **Database Transactions** | Использование `DB::transaction()` для гарантии того, что либо все изменения в БД применятся, либо ни одно. |
| 10 | **Custom Middleware** | Создание своего посредника для обработки специфических заголовков или проверки кастомных условий доступа. |
| 11 | **RabbitMQ в Laravel** | Laravel не поддерживает его нативно (только через пакеты). Используется для обмена сообщениями между микросервисами. |
| 12 | **Redis: Rate Limiting** | Ограничение количества запросов к API в единицу времени, часто реализуется через Redis. |
| 13 | **Clickhouse для логов** | Использование Clickhouse для хранения и анализа огромных массивов событий, которые Eloquent не переварит. |
| 14 | **CI/CD: Laravel Sail/Docker** | Использование Docker для локальной разработки и обеспечения идентичности окружений на Dev и Prod. |
| 15 | **Eloquent: Accessors & Mutators** | Методы `get...Attribute` и `set...Attribute` (или новые `Attribute` в PHP 8) для форматирования данных модели. |

## 🔴 Уровень: Senior (Архитектура и масштаб)

| # | Вопрос | Ответ |
| :--- | :--- | :--- |
| 1 | **Service Provider: Register vs Boot** | `register` — только для связывания в контейнере, `boot` — для логики, где нужны уже зарегистрированные сервисы. |
| 2 | **Contextual Binding** | Возможность внедрять разные реализации одного интерфейса в разные классы через Service Container. |
| 3 | **Repository vs Action Pattern** | `Repository` — абстракция над БД, `Action` — вынос одной бизнес-задачи в отдельный класс (Single Responsibility). |
| 4 | **Eloquent: Lazy vs Eager Loading** | Как на уровне архитектуры запретить Lazy Loading (`Model::preventLazyLoading()`), чтобы избежать N+1 на проде. |
| 5 | **K8s: Horizontal Scaling** | Проблемы Laravel в K8s: хранение сессий (нужен Redis), общие файлы (нужен S3) и работа планировщика (Cron). |
| 6 | **Event Sourcing в Laravel** | Подход, при котором состояние системы восстанавливается из цепочки событий (использование пакета spatie/laravel-event-sourcing). |
| 7 | **Оптимизация БД: Индексы** | Анализ сложных запросов через `EXPLAIN`, использование составных и покрывающих индексов в миграциях. |
| 8 | **Zero Downtime Deployment** | Организация деплоя так, чтобы пользователи не видели ошибок (использование Envoyer или кастомных скриптов с симлинками). |
| 9 | **Microservices: HTTP vs Queues** | Когда использовать синхронные вызовы (Guzzle/Http Client), а когда асинхронный обмен через брокеры. |
| 10 | **Custom Eloquent Casts** | Создание своих классов для приведения типов полей БД к сложным объектам (например, Value Objects). |
| 11 | **Unit vs Integration Testing** | Как правильно мокать (Mock) зависимости в Service Container при написании тестов на сложные сервисы. |
| 12 | **Observability: Трейсинг** | Интеграция Laravel с OpenTelemetry или инструментами вроде Sentry для глубокого анализа цепочек запросов. |
| 13 | **Dead Letter Queue (DLQ)** | Стратегия обработки проваленных Job'ов: ретраи, экспоненциальная задержка и ручной разбор ошибок. |
| 14 | **Multi-tenancy** | Архитектура для SaaS: разделение данных разных клиентов на уровне БД (отдельные базы или глобальные Scopes). |
| 15 | **Laravel Octane** | Использование Swoole или RoadRunner для того, чтобы не загружать фреймворк на каждый запрос, ускоряя его в разы. |
